- Preprocessing currently applies to BM25/FTS5 only: collection text is transformed at index time and queries at search time; original text feeds embeddings, vector search, and reranking.
- Collections remain the ownership/path boundary. Code, configuration, and related data should be optional auxiliary domains with separate indexes and score distributions, supporting—not directly competing with—primary documents.
- Auxiliary retrieval may use deterministic AST extraction, typed/confidence-bearing edges, one-hop graph propagation, hub normalization, and provenance. Keep propagation bounded; community detection is deferred.
- Code vectors are optional and should embed structured symbol representations, activating related primary documents through graph edges rather than competing with document scores.
- A fast classifier/encoder is primarily a candidate judge or reranker. It cannot recover documents absent from the candidate pool; bilingual rescue therefore requires multilingual vectors, bilingual lexical expansion, or an alias/concept graph.
- Proposed low-latency flow: BM25 plus auxiliary evidence and graph propagation first; return decisive results early; use a fast relevance judge for uncertain candidates; invoke multilingual vector retrieval only for weak lexical coverage.
- Mixed-language BM25 can match shared surface terms but cannot bridge translated terms such as “캐시 무효화 정책” and “cache invalidation policy.” Language-neutral anchors such as symbols, paths, and configuration keys may provide a model-free bridge.
